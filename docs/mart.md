# Аналитическая витрина Seoul Bike Sharing Demand

## 1. Модель

Для лабораторной работы выбран основной аналитический вопрос из Project Brief:

> В какие часы суток и сезоны наблюдается различный уровень почасового спроса на велосипеды и как этот спрос отличается между праздничными и обычными днями?

Для ответа на вопрос построена одна широкая аналитическая таблица `hourly_rentals`.

**Гранулярность:** одна строка таблицы `hourly_rentals` представляет один час наблюдения системы велопроката Seoul Bike в определённую календарную дату.

**Составной бизнес-ключ:** `date + hour`.

В результате проверки установлено, что компоненты ключа не содержат пропусков, а повторяющиеся сочетания `date + hour` отсутствуют.

**Основная мера:** `rented_bike_count` — количество арендованных велосипедов за один час.

Единица измерения — велосипеды за час.

Значения `rented_bike_count` допускается суммировать по непересекающимся часовым наблюдениям, например по дням или сезонам. `COUNT(*)` при этом обозначает количество часовых наблюдений, а не количество арендованных велосипедов.

Для ответа на выбранный аналитический вопрос используются следующие основные срезы:

- `hour` — час суток;
- `season` — сезон;
- `holiday` — праздничный или обычный день;
- `date` — календарная дата;
- `month` — календарный месяц;
- `day_of_week` — ISO-номер дня недели.

Также сохранены признак функционирования сервиса, логическая дата загрузки исходных данных и quality-флаги, сформированные в ЛР № 3.

Использована одна широкая таблица, поскольку все необходимые для выбранного вопроса показатели и описательные признаки имеют одинаковую часовую гранулярность. Выделение отдельных таблиц измерений в данном случае не требуется и не упрощает ответ на выбранный вопрос.

Исходный уровень детализации сохранён. Фильтрация строк при формировании витрины не выполнялась:

`8760 строк staging = 8760 строк mart`.

Витрина сохранена по пути:

`s3://mart/seoul_bike_sharing_demand/source_ingested_on=2026-10-13/hourly_rentals.parquet`

## 3. Проверки и ограничения

Полные SQL-запросы и результаты проверок приведены в разделе проверки витрины ноутбука `notebooks/build_mart.ipynb`.

После материализации `hourly_rentals.parquet` был повторно прочитан непосредственно из SeaweedFS.

Основные результаты проверки:

- количество строк staging — 8760;
- количество строк mart — 8760;
- пропуски в компонентах ключа `date + hour` отсутствуют;
- повторяющиеся значения составного ключа отсутствуют;
- `rented_bike_count` находится в диапазоне от 0 до 3556;
- `hour` находится в диапазоне от 0 до 23;
- `month` находится в диапазоне от 1 до 12;
- `day_of_week` находится в диапазоне от 1 до 7;
- quality-флаги из ЛР № 3 перенесены без изменения;
- скрытая фильтрация строк не выполнялась.

Проверочный запрос выполнил группировку по `season`, `holiday` и `hour` с расчётом количества часовых наблюдений и среднего `rented_bike_count`. Было получено 192 группы, что соответствует сочетаниям четырёх сезонов, двух значений праздничного статуса и 24 часов суток.

Таким образом, витрина содержит необходимую меру и срезы для ответа на выбранный аналитический вопрос.

Основные ограничения:

1. Данные относятся только к Сеулу и охватывают период с декабря 2017 года по ноябрь 2018 года.
2. Значение `rented_bike_count` является агрегированным числом аренд за час. Витрина не позволяет анализировать отдельные поездки, пользователей, велосипеды или станции.
3. Часы, в которые сервис не функционировал, сохранены в витрине с `functioning_day = false`. Они не удалялись, поскольку такое решение о качестве не принималось в ЛР № 3.
4. Витрина предназначена для анализа почасового спроса по выбранным календарным срезам. Полный содержательный анализ и интерпретация показателей выполняются на следующих этапах проекта.
